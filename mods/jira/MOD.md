## What it does
Lists my open Jira issues plus the backlog of one or more projects (keys comma-separated, e.g. `DA, OPS`; one section per project). The filter button next to search opens a popover with Sort (Updated or Created, newest first, my issues and backlogs; in a sprint group in-progress issues still come first), Group by (Sprint, Status, Parent — the epic of a story/task or the issue of a sub-task, from Jira's `parent` field, "No parent" last — or None; my issues), "Show project backlog" (off = its request is not made), "Current sprint only" (no other sprints, no backlog) and a checkbox per status found in the loaded issues (To Do, In Progress, QA, …, with counts; none checked = all); the button shows how many filters are on. Each row shows the issue type's icon (Jira's own, see Settings and data; else the mod's, picked by the type's name: sub-task, bug, story, epic, customer ticket, PM/QA, security, investigation, else task), the key, the status and the age since creation ("today", "5d ago"). Click opens the issue in the browser; right-click copies the task ID or starts an agent session. The issue whose key is in the focused terminal's branch (a worktree's `DPM-1143-…`; for a focused mod pane such as wb-diff, a terminal's of the focused tab) is highlighted: selected background and an accent left border, as prs marks the current branch's PR. The last issue opened by a click keeps only a faint (hover) background.

The mic button next to search is voice input (`voice.js`, the same as the history mod's): hold it, speak, release (anywhere in the panel); whisper-cpp turns the speech into text on this Mac, `claude -p` (sonnet) cleans it up (numbers, task keys, English terms), and it goes into the search box with the cursor there, filtering the list as typing does (`DA-1348` said as "ді ей тринадцять сорок вісім"). Without ffmpeg, whisper-cpp or its model, a setup card with the install commands replaces the list.

Under an issue, each open pull request of any space's repo whose title or head branch contains the issue key (any `[A-Za-z][A-Za-z0-9_]*-\d+` word, upper-cased, e.g. `DA-123: …` or `feature/da-123-…`) gets a small line: CI dot (green passed, red failed, yellow running, grey none), a Copilot badge "C" as in prs (red while a High or Medium Copilot thread, or one of unknown severity, is unresolved; blue when only Low ones are open; green once it reviewed and none are open; yellow spinner while it is reviewing; faint when not run; open threads and pending Copilot requests from one GraphQL call per repo, first 50 PRs × 100 threads; severity from Copilot's latest overview review, so a thread from an older overview counts as High), approval icon (green approved, red changes requested, grey not yet), a red triangle for merge conflicts, a purple draft icon, `#number`, the head branch, the target as `→ base`, the author's login on the right (as the prs mod shows them) and a go-to button (accent while a terminal is on the head branch: selects that space and focuses the pane; else opens the branch's worktree, from `git worktree list --porcelain`, in its space or a new one; neither: a toast saying it isn't checked out); the tooltip spells them out. Click opens our `prs` mod's PR dialog (`openOverlay({mod: "prs", props: {pr}})` with `{number, url, isDraft, repo: {cwd, on}}`) when `~/.config/herdr-app/mods/prs/main.js` exists, else the PR in the browser. The list doesn't depend on which terminal is focused: the repos are those of every space's terminal folders (each folder's `origin` remote, so worktrees of one repo count once). One `gh pr list --state open --limit 100` per repo (with `latestReviews`, not `reviews`: Copilot's long bodies doubled the time), in parallel, on open, Refresh and auto-sync; a space opened later shows its PRs after the next of those. Without gh, outside a repo or when gh fails, no PR lines (a repo's last good list stays).

The row's terminal button (and "Start <agent> session…" in the menu) opens a "Start session" dialog for the focused folder (the focused pane's; for a mod pane such as wb-diff, a terminal of the focused tab, else of the active space; the space's folder last) with an editable branch name (`<key>-<first words of the title>`) and base branch (origin's default), and two choices:
- New worktree (default): a worktree for the branch next to the main checkout, then a space there running the agent with the task.
  - Reuse: before creating, the mod runs `git worktree list --porcelain` in the main checkout. A worktree that already has the branch is reused: its space is selected if one is open on that folder (same machine), else a new space opens there. A local branch with no worktree gets `git worktree add <path> <branch>`. Otherwise `git fetch origin <base>` and `git worktree add -b <branch> <parent>/<repo>-<branch> origin/<base>` (next to the main checkout, e.g. `~/Projects/dokka/dokka-backend-DA-123-…`), then `space.new {name, folder, machine, argv, task}`.
- New branch here: `tab.new {name, folder, argv, task}`; the task tells the agent to fetch and create the branch from `origin/<base>` (stopping to ask if the tree has uncommitted changes), then work on the issue.
Prompt (both choices): `<key>: <title> — Task description: <description> — …`. The description is fetched at start time (`GET /rest/api/3/issue/<key>?fields=description`), flattened from Atlassian Document Format to one line of at most 3000 characters; if the fetch fails it is left out. The rest tells the agent to copy the gitignored files the worktree needs (env files, certificates, local config) from the main checkout as the repo's own docs say, install dependencies, then work on the issue. The task is one line (a newline could send it early).
If our `history` mod is installed here (`~/.config/herdr-app/mods/history/main.js` exists), and the space is on this machine, the dialog holds it below the form (a two-block `layout`: jira with `{start}`, history with `{query: <key>, folder, embedded: true}`), listing past sessions that mention the task key in the dialog's folder's project; history's Resume closes the whole dialog (both blocks share `props().overlay`). Without the mod, or on a remote space, the dialog is the form alone.
Outside a git repo the dialog only starts the agent there with `<key>: <title>` and the description. The worktree is not removed by this mod; Herdr's worktree mod can remove it. The agent is picked in the settings form from Herdr's `knownAgents()` (installed ones on the active space's machine; programs.json can add more) and saved at once as `jira.settings.agent` / `agentName`; default Claude Code. A settings form saves site, project and credentials (email and API token).

## Files
- main.js: UI, Jira requests, Keychain access, settings form, PR lines.
- voice.js: copy of lib/voice.js (mic button, recording, whisper, setup card); edit lib/voice.js, then scripts/sync-lib.
- pr-badges.js: CI, approval and Copilot badges and the Copilot GraphQL call, shared with prs (copy of `lib/pr-badges.js`; edit it there and run `scripts/sync-lib`).
- jira.svg, refresh.svg, session.svg, settings.svg, filter.svg, check.svg, mic.svg: icons.
- approved.svg, changes.svg, conflict.svg, draft.svg, spinner.svg: PR line icons (copies of the prs mod's); goto.svg: the go-to button.
- type-*.svg (task, bug, story, epic, subtask, customer, pmqa, security, investigation): fallback issue type icons, colored outlines like Jira's (full color, via image()).
- gpui-kit.d.ts, jsconfig.json: editor typings only.

## Settings and data
- Keychain service `herdr-jira` (account = email, password = API token), via `security`.
- Shared state `jira.settings` ({ site, project ("DA, OPS"), base, agent, agentName, sort ("updated" | "created"), groupBy ("sprint" | "status" | "parent" | "none"), backlog (false = hidden) }).
- Status order (status groups, the status list in the filter): the columns of each project's board, left to right, read once per session from `GET /rest/agile/1.0/board?projectKeyOrId=<key>` and `/board/<id>/configuration` (first scrum board, else first board; the saved projects and those of my issues, at most 5). Statuses on no board go after them: to do, in progress, done, then by name. A token with scopes also needs read:board-scope:jira-software and read:board-scope.admin:jira-software for this; without them the fallback order is used.
- `data/jira/types/<type id>-<avatar id>.svg`: Jira's issue type icons (the type's `iconUrl`, fetched with the credentials through the API base), saved once and kept across restarts; after a refresh, types not seen this session are looked up. Only SVG is kept (Herdr's fetch reads text); a PNG icon or a failed fetch falls back to the mod's own. Delete the folder to fetch them again.
- Fetches the 100 latest-updated of my issues and the top 100 (by rank) of the backlogs, then sorts them locally.
- `localStorage` `current` ("1" / "0"): the current-sprint filter; `statuses` (JSON list of status names, at most 50): the status filter.

## Notes
- TEMPORARY (voice.js): right-click the mic switches the voice engine between whisper and macOS's own recognizer (needs Dictation on and `~/.local/share/herdr-voice/STT.app`), saved in `localStorage` `voice.engine`; see the history mod's MOD.md. To be removed once one engine wins.
- PRs are kept in memory only: the repos some space points at (repos no space points at leave on the next load; folder → repo for the last 50 folders); each PR keeps only its line's fields. CI, approval and the Copilot badge come from `pr-badges.js`, the same helper prs uses, so both mods show a PR alike. Per load: one `gh pr list` and one `gh api graphql` per repo.
- Loads once on open; refreshes every 5 min only when the Auto checkbox in the header is on (off by default, saved in `localStorage` `jira.auto`).
- Uses an API token, not OAuth; the token is briefly in `security` argv when saved (noted in code).
- macOS only (Keychain); standalone.
