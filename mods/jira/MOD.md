## What it does
Lists my open Jira issues plus the backlog of one or more projects (keys comma-separated, e.g. `DA, OPS`; one section per project). The filter button next to search opens a popover with Sort (Updated or Created, newest first, my issues and backlogs; in a sprint group in-progress issues still come first), Group by (Sprint, Status, Parent — the epic of a story/task or the issue of a sub-task, from Jira's `parent` field, "No parent" last — or None; my issues), "Show project backlog" (off = its request is not made), "Current sprint only" (no other sprints, no backlog) and a checkbox per status found in the loaded issues (To Do, In Progress, QA, …, with counts; none checked = all); the button shows how many filters are on. Each row shows the issue type's icon (Jira's own, see Settings and data; else the mod's, picked by the type's name: sub-task, bug, story, epic, customer ticket, PM/QA, security, investigation, else task), the key, the status and the age since creation ("today", "5d ago") on the first line, and the summary under the key on the second, as prs lays out a PR (icons of the same size). Click opens the issue in the browser; right-click copies the task ID or starts an agent session. The issue whose key is in the focused terminal's branch (a worktree's `DPM-1143-…`; for a focused mod pane such as wb-diff, a terminal's of the focused tab) is highlighted: selected background and an accent left border, as prs marks the current branch's PR. The last issue opened by a click keeps only a faint (hover) background.

The mic button next to search is voice input (`voice.js`, the same as the history mod's): hold it, speak, release (anywhere in the panel); whisper-cpp turns the speech into text on this Mac, `claude -p` (sonnet) cleans it up (numbers, task keys, English terms), and it goes into the search box with the cursor there, filtering the list as typing does (`DA-1348` said as "ді ей тринадцять сорок вісім"). Without ffmpeg, whisper-cpp or its model, a setup card with the install commands replaces the list.

An issue with open pull requests (of any space's repo, whose title or head branch contains the issue key: any `[A-Za-z][A-Za-z0-9_]*-\d+` word, upper-cased, e.g. `DA-123: …` or `feature/da-123-…`) shows a PR icon at the right of its first line, with the count from two PRs on. Its color: red when a PR has failed CI, merge conflicts or requested changes; yellow while CI runs; green when every PR is approved; else dim. Clicking it shows or hides the PR lines under the issue (hidden by default, not saved). Each PR line has: CI dot (green passed, red failed, yellow running, grey none), a Copilot badge "C" as in prs (red while a High or Medium Copilot thread, or one of unknown severity, is unresolved; blue when only Low ones are open; green once it reviewed and none are open; yellow spinner while it is reviewing; faint when not run; pending Copilot requests from the list query, open threads from the second query, 30 per PR; severity from Copilot's latest overview review, so a thread from an older overview counts as High), approval icon (green approved, red changes requested, grey not yet), a red triangle for merge conflicts, a purple draft icon, `#number` (`repo #number` when the issue's PRs are in more than one repo), the head branch, the target as `→ base`, the author's login on the right (as the prs mod shows them) and a go-to button (accent while an agent on the issue sits on the head branch; it does what the session button does, for this PR: see below); the tooltip spells them out. Click opens our `prs` mod's PR dialog (`openOverlay({mod: "prs", props: {pr}})` with `{number, url, isDraft, repo: {cwd, on}}`) when `~/.config/herdr-app/mods/prs/main.js` exists, else the PR in the browser. The list doesn't depend on which terminal is focused: the repos are those of every space's terminal folders (each folder's `origin` remote, so worktrees of one repo count once). One `gh api graphql --cache 60s` per repo (`openPrs` in `pr-badges.js`: the newest-updated 50 open PRs with the checks' rollup state, latest reviews and review requests, ~2 GraphQL points; plus, only for PRs Copilot left comments on, a second cached query for their unresolved threads), in parallel, on open, Refresh and auto-sync; a space opened later shows its PRs after the next of those. The prs mod sends the exact same query, so gh's disk cache answers whichever mod asks second within 60 s. A repo with no lines yet first gets gh's cached answer up to a day old (`--cache 24h`, ~0.2 s, shown at once), then the fresh one replaces it. Refresh asks GitHub past the cache (`--cache 1s`), which replaces the cached answer for every mod, then sets `jira.refreshed` so an open prs panel shows it; a `prs.refreshed` from the prs mod's Refresh makes a plain load that shows its fresh answer here. Without gh, outside a repo or when gh fails, no PR lines (a repo's last good list stays).

The row's terminal button and a PR line's go-to work the same way (go-to for its PR; the terminal button for the issue's PR when it has exactly one):
1. An agent already on the issue, in any space (its tab name or title names the key; on the PR's branch first; the latest active one), gets the focus: space.select, pane.focus. Never a second copy of a running session.
2. Otherwise always the "Start session" dialog ("Start <agent> session…" in the right-click menu opens it too):
   - Folder, so the dialog lands in the issue's repo whichever space is active: a terminal already on the issue's branch (the PR's, else one naming the key, any repo); else for a PR the focused folder when it is in the PR's repo, else the folder the PR was loaded from; else the issue's latest past session in any project (`human-history search <key> -f all` from home, this machine): its worktree when it still exists, else its repo's main checkout; else the focused folder (the focused pane's; for a mod pane such as wb-diff, a terminal of the focused tab, else of the active space; the space's folder last).
   - Branch (editable): the PR's branch, else an existing branch naming the key (local first, then origin's), else `<key>-<first words of the title>`; its kind is shown (PR branch, existing, on origin, or new from `origin/<base>`, with the base field only then).
   - The dialog has two parts: WHERE (the folder and branch the agent works in) and SESSION (the conversation it starts with).
   - Where: "New worktree" next to the main checkout (`<parent>/<repo>-<branch>`), or "Its worktree" when the branch has one (`git worktree list --porcelain`); or "Here" (picked when the folder is already on the branch): the folder switches to it, refused while it has uncommitted changes to tracked files or another worktree has the branch.
   - Session: a "New <agent> session" card first, picked, then one card per past session on the issue, to resume — up to 5 from human-history (`human-history search <key> --json -f repository` in the repo, all worktrees; ranked: the key in both the session's title and its branch, then in the title only, then in the branch only, then in my own prompt; within each, more messages naming the key (`hits`), then the latest activity; an assistant's passing mention doesn't count), each with its title, agent, age, branch and folder. The body scrolls when they don't fit.
   - Start: git puts the branch in place — a local branch as is; origin's fetched and tracked (`worktree add --track -b` / `checkout --track -b`); else a new branch from `origin/<base>` (fetched). Then the agent opens in a new tab of the space that already shows that folder, else a new space (worktree) or the active one (here), named `<key> <first words of the title>`. Resume: `claude --resume <id>`, `codex resume <id>`, … (human-history's table), with a "Resumed <key>" toast; a Claude session from another folder has its conversation file copied into that folder's `~/.claude/projects/<path>` first (as the history mod does), and a failed copy starts a new session. New: the agent from settings with a one-line task `<key>: <title> — Task description: <description> — …` (description fetched at start, ADF flattened, at most 3000 characters, left out on failure): a new worktree — prepare it (copy the gitignored files it needs from the main checkout as the repo's docs say, install dependencies) and work on the issue; an existing worktree or branch here — read the issue and the PR or the branch's changes, summarize and wait; a new branch here — work on it.
   - A PR from a fork fails at the fetch with git's message. No human-history or a remote space: no past session, only New.

Outside a git repo the dialog only starts the agent there (or resumes) with `<key>: <title>` and the description. The worktree is not removed by this mod; Herdr's worktree mod can remove it. The agent is picked in the settings form from Herdr's `knownAgents()` (installed ones on the active space's machine; programs.json can add more) and saved at once as `jira.settings.agent` / `agentName`; default Claude Code. A settings form saves site, project and credentials (email and API token).

## Files
- main.js: UI, Jira requests, Keychain access, settings form, PR lines.
- voice.js: copy of lib/voice.js (mic button, recording, whisper, setup card); edit lib/voice.js, then scripts/sync-lib.
- pr-badges.js: CI, approval and Copilot badges and the cached open-PRs GraphQL call (`openPrs`), shared with prs (copy of `lib/pr-badges.js`; edit it there and run `scripts/sync-lib`).
- jira.svg, refresh.svg, session.svg, settings.svg, filter.svg, check.svg, mic.svg: icons.
- approved.svg, changes.svg, conflict.svg, draft.svg, spinner.svg: PR line icons, pr.svg: the issue's PR icon (copies of the prs mod's); goto.svg: the go-to button.
- type-*.svg (task, bug, story, epic, subtask, customer, pmqa, security, investigation): fallback issue type icons, colored outlines like Jira's (full color, via image()).
- gpui-kit.d.ts, jsconfig.json: editor typings only.

## Settings and data
- Keychain service `herdr-jira` (account = email, password = API token), via `security`.
- Shared state `jira.settings` ({ site, project ("DA, OPS"), base, agent, agentName, sort ("updated" | "created"), groupBy ("sprint" | "status" | "parent" | "none"), backlog (false = hidden) }).
- Status order (status groups, the status list in the filter): the columns of each project's board, left to right, read once per session from `GET /rest/agile/1.0/board?projectKeyOrId=<key>` and `/board/<id>/configuration` (first scrum board, else first board; the saved projects and those of my issues, at most 5). Statuses on no board go after them: to do, in progress, done, then by name. A token with scopes also needs read:board-scope:jira-software and read:board-scope.admin:jira-software for this; without them the fallback order is used.
- `data/jira/types/<type id>-<avatar id>.svg`: Jira's issue type icons (the type's `iconUrl`, fetched with the credentials through the API base), saved once and kept across restarts; after a refresh, types not seen this session are looked up. Only SVG is kept (Herdr's fetch reads text); a PNG icon or a failed fetch falls back to the mod's own. Delete the folder to fetch them again.
- Fetches the 100 latest-updated of my issues and the top 100 (by rank) of the backlogs, then sorts them locally.
- `localStorage` `current` ("1" / "0"): the current-sprint filter; `statuses` (JSON list of status names, at most 50): the status filter.

## Notes
- TEMPORARY (voice.js): right-click the mic switches the voice engine between whisper and macOS's own recognizer (needs Dictation on and `~/.local/share/herdr-voice/STT.app`), saved in `localStorage` `voice.engine`; see the history mod's MOD.md. To be removed once one engine wins.
- PRs are kept in memory only: the repos some space points at (repos no space points at leave on the next load; folder → repo for the last 50 folders); each PR keeps only its line's fields. CI, approval and the Copilot badge come from `pr-badges.js`, the same helper prs uses, so both mods show a PR alike. Per load: one `gh api graphql` per repo (two, the first from gh's cache, for a repo with no lines yet).
- `data/jira/issues.json`: the last loaded issues (only the fields rows, groups and sorting read, ~40 KB), with the site and the board status order. A new copy of the panel (another tab, a reload) shows it at once while the fresh load runs, so there is no "Loading…" in between; written after each load only when it changed; ignored for another site.
- Loads once on open; refreshes every 5 min only when the Auto checkbox in the header is on (off by default, saved in `localStorage` `jira.auto`).
- Uses an API token, not OAuth; the token is briefly in `security` argv when saved (noted in code).
- macOS only (Keychain); standalone.
