## What it does
Lists open PRs authored by me plus those where my review is requested (two gh calls), or with the header's Mine/All switch every open PR (first 100, via gh; the "Copilot reviewed" toast stays for PRs I opened; no sound). A PR waiting for my review (requested from me by login, not via a team) has a yellow eye icon. The list is grouped: "Mine" (opened by me) on top, then "Others" with those waiting for my review first (no grouping when one group is empty or my login is unknown). The list covers PRs in the repo of the focused folder (when a mod pane such as a wb-diff tab is focused, the last terminal folder of that space), with CI, review, approval and Copilot-review state. The PR whose head branch is the focused terminal's branch (`panes()` branch; for a fork PR also the local `pr-<n>-<branch>`) is highlighted with the theme's selected background and an accent left border. Each row shows the head branch, then the target branch as `→ base`. A PR with a label containing "hotfix" has its title in the theme's red (ansi1 mixed 60:40 with the text colour, so it doesn't glare). A PR with merge conflicts (gh `mergeable` is `CONFLICTING`) has a warning triangle in the same softened red. A row whose title starts with a task key (`[A-Za-z]+-\d+`, e.g. `DA-20323`) has a copy button for that key. The Copilot badge is red while a High or Medium Copilot thread (or one of unknown severity) is unresolved, blue when only Low ones are open (severity from Copilot's overview reviews, matched by thread URL), green once it reviewed and none are open, a yellow spinner while it is reviewing (requested, including a re-request after an earlier review; updates on the 2-minute poll), faint when not run (pending Copilot request and open threads: one GraphQL call per repo per poll, first 50 PRs × 100 threads; gh's own reviewRequests leaves bots out). Click opens a dialog with description, comments, reviews and the unresolved line-comment threads (gh GraphQL, first 100 threads × 30 comments; resolved ones are hidden). Copilot's latest overview review (`ccr-overview-v2`) is shown as a card like GitHub's: verdict, summary, open issues with a High/Medium/Low pill; a click unfolds the issue's thread in place (file:line, Copilot's explanation and replies, an "Open on GitHub" link), or opens GitHub when the thread wasn't loaded (issues whose thread is resolved are left out; threads shown in the card are not repeated in the open-threads list), a folded "What changed" and the review effort; an overview in another layout stays a plain comment; buttons open the PR in the browser, copy the link, approve, or generate an AI review.
A row button (and "Work in worktree" in the PR popup) creates a git worktree on the PR branch next to the main checkout (`<repo>-<branch>`; a fork PR gets branch `pr-<n>-<branch>` fetched from `pull/<n>/head`) and opens a new space there with an agent (claude if installed, else the first installed) whose prompt is the PR with its full description, asking it to prepare the worktree and address the review comments. If the branch already has a worktree, its space is selected (or a new one opened there). The button spins while it starts; errors come as a notification.
A create-PR dialog (the header's + button) pushes the branch and runs gh pr create, with an AI-written title and description.

## Files
- main.js: panel view, gh calls, PR detail and create dialogs.
- ai.js: AI model settings and runner shared across mods (copy of `lib/ai.js`; edit it there and run `scripts/sync-lib`): claude/codex CLIs or a local server.
- approved.svg, changes.svg, conflict.svg, copy.svg, draft.svg, plus.svg, pr.svg, refresh.svg, review.svg, session.svg, spinner.svg: status and button icons.
- gpui-kit.d.ts, jsconfig.json: editor typings only.

## Settings and data
localStorage `prs.auto` (old unprefixed `auto` is read as fallback): auto-refresh on/off (off until switched on); `prs.all`: the Mine/All switch. Shared `wb.ai.*` keys hold the AI model list, per-use model and per-project templates (owned by the wb-ai mod; migrated from older `wb.*` keys). No keychain.

## Notes
Polls gh every 2 min only when auto is switched on (off by default) and the panel is shown: the prs block in `layout()` is not hidden and is the active child of its stack (a prs block not found in the layout counts as shown). When the panel comes into view with auto on and the list is older than 2 min (or the focused repo was never loaded), it refreshes at once in the background (within the 2 s tick). Refresh, `prs.changed` and the Mine/All switch poll at any time (my login for the popup comes from gh's disk cache, `gh api user --cache 24h`); while a refresh runs only the refresh icon spins, the list is replaced when new data arrives (a failed gh or GraphQL call keeps the last good list and Copilot badges). It checks the focused folder and prs.changed every 2 s (cheap compare). In memory each PR keeps only its row fields (CI, approval and Copilot badges worked out per poll, body cut to 500 chars for search); repos no space points at are dropped on the next poll. Diff sent to AI is capped at 60000 chars. For the PR title and description the AI also gets the repo's own rules: the GitHub PR template, then the tracked agent docs that mention pull requests most (`CLAUDE.md`, `AGENTS.md`, `.claude/**/*.md`, `.github/**/*.md`, `.cursor/**`), then `CLAUDE.md`; at most 6 files, 8000 chars each. gh and AI calls have timeouts (120-600 s). Works without the `wb.ai.*` keys but AI features need a model configured in wb-ai.
- ai.js is a per-mod copy (isolation rule) of `lib/ai.js`, like wb-ai's; the `wb.ai.*` settings are shared on purpose with wb-ai, prs and changes-copy (documented contract, optional where read, defaults are created).
