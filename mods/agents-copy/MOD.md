## What it does
Lists agents like the shipped `agents` panel, in Priority or Grouped by space, with sub-agents in a block under their parent's card, pins and a narrow rail mode. Cloned from agents 0.1.15; the 0.1.17 fixes are ported (names keep a leading emoji or bracket, a kept sub-agent shows its own done, the rail marks the focused agent).

- Cards: every agent, in every state, is the same card (rounded, 1px border, no fill). Left column: the program icon with the status glyph under it (a 16 px slot only when there is a glyph, so a card with one line and no chips is one line high). Glyph: spinner when working, a red circle with a pulsing `?` when blocked, a check in a 16 px accent circle when done and unseen (the unread mark), none when idle (seen cards are not dimmed). Line 1, the same rule for every card: the tab's name when it was given one (not the program's name or key), else the agent's report (terminal `report`, else its title), else the program name; time in state on the right (hover shows the pin button). Line 2: the report or title only when it says more than line 1. When one starts with the other (a tab name cut with `…`), the card shows one line, the longer text, in line 1. A Jira key that line 1 already starts with is dropped from line 2, and the key shown in the Jira chip is dropped from both lines. Line 2 wraps up to two lines, then cut off. Without line 2, line 1 wraps up to two lines and the eye button sits at its end. An agent in a git folder always gets its branch (`main` included; not a detached `HEAD`) as a dim line under line 1. In the priority and pinned views (no space header above) the space name goes dim at the end of the bottom row, unless the branch line is there. The PR and Jira chips, when there are any, sit on their own row at the bottom of the card (under line 2 and the open last message), so the name and the report keep the card's width. Blocked cards are red-tinted with red text; idle (seen) cards are dimmed. The focused agent's card (the one being worked with) has the selected fill (border in the same colour), as the shipped agents list (a blocked one keeps its red tint). The branch is the line under line 1 (see below). Sub-agents sit right under their parent's card (indented 12 px), each as a small card built by the same code as the parent's (`card()`): icon with the status glyph under it, name and time in state (stamped like cards; paneless sub-agents too), report or title with the eye button (last message), and the focused/blocked colours; a deeper sub-agent's card is indented 12 px more per level.
- Priority view: groups Needs you, Working, Done (colored dot, title, count); idle agents are cards without the unread check at the end of Done. Grouped view uses the same cards under the space headers; spaces on worktrees of one git repo (same git common dir) share one group, named after the repo folder (not a space: a space's folder is only where it started), and a card whose space has another name names that space in line 1.

- PR chip: a small pill on the chip row with `#<n>` and a check glyph (red failing, green passing, yellow pending, grey none). Click opens the PR in the browser (`gh pr view --web`). No chip without an open PR, for agents on other machines, or in rail mode. An agent that names a Jira key (title, tab, name, report; only keys of `jira.settings.project` when it is saved) gets the open PR whose branch has that key, even when its folder is on another branch (two agents on one branch each show their own task's PR); with no such PR it gets the folder branch's PR only when that branch names no Jira key. Otherwise the PR is found by the agent's folder and branch, so agents in the same folder share it; when the branch names a Jira key (e.g. `DA-20457-…`) and some of those agents mention the key (title, report, tab or name, case-insensitive), only they get the chip (and match the PR filter). If none mentions it, the ones that mention another Jira key (of `jira.settings.project` when it is saved) lose the chip and the rest keep it.
- Jira chip: an accent pill with a Jira key (e.g. `DA-20457`) before the PR chip; click opens `<site>/browse/<key>` with `open`. The key is its branch's key when any of its texts mention it, else the first one the agent names (title, tab, name, report) whose project is in `jira.settings.project` (any project when none is saved), else its branch's key, given by the same rule as the PR chip among agents sharing a folder and branch. So two agents on one branch each show their own task. The site is `jira.settings.site`, written by the `jira` mod; without it there is no chip. Not in rail mode.
- Filter (funnel button in the header): one space or all, and PR: Any / Has PR / Checks failing / No PR. An active filter shows a chip with a clear button and an accent-colored icon. It applies to both views and to the order used by agent.next/prev.
- Asking: an agent that finished (done or idle) on a choice menu counts as blocked: Needs you group, red tint, pulsing `?`, ordered and reminded like a blocked one (its time counts from when it was detected). It stays so until the screen is re-read without a menu (turn, done-to-idle or title change) or it starts working.
- Search (magnifier button in the header, not in rail mode): opens a box under the header, focused. Text filters (case-insensitive substring) by program, name, template, title, report, space and tab names, and the names of its sub-agents; it applies after the filter. Esc, the x, or a click on an agent or sub-agent row (going to it) closes it and clears the text. When nothing matches, "Clear" empties the text and keeps the box open. The space/PR filter is not reset.
- Sub-agents without a pane (started with `hc run`) are rows under their parent. A click gives one a pane with `terminal.keep` (it lands in its parent's tab; the core may apply it a moment later), then focuses it after one-shot checks at 0.4 s and 1.6 s; if no pane appears or the keep fails, it is peeked (`terminal.peek`) instead. A sub-agent that already has a pane is focused.
- Last message (experiment): an eye button at the end of line 2 (also on a sub-agent's card) expands that card. One `hc read <address> --lines 0` (the visible screen) gives the last message: the person's prompt (`❯ ` line, labelled YOU) or the agent's reply (`⏺` block, tool calls skipped, labelled AGENT), whichever is lower above the input box, up to 12 lines, in a box under line 2 ("Loading…", "No message on screen" or "Could not read the screen" otherwise). While open it reads again when that agent's turn or status changes (no timer; one read at a time, a change meanwhile reads once more; the last good message stays on a failed read). One card is open at a time; the eye again, a press anywhere outside the open card, or a click on a card collapses it, and the text is dropped. Not for agents on other machines.
- Reminders: while an agent stays blocked (or asking), a repeat warning toast and the `blocked` sound come every 2, 5 (default) or 10 minutes (or off), set in the sort popup. Herdr's own first toast and sound are not duplicated. Not sent for the agent you are looking at in an active window. Several due at once give one toast naming the count, focusing the longest-waiting.

## Files
- main.js: the view, popups, reminders.
- prs.js: gh PR lookups and Jira key helpers (state is kept by the view instance). Copy of `lib/prs.js`; edit it there and run `scripts/sync-lib`.
- headline.js: the rule for a card's line 1 and line 2, shared with agents-board. Copy of `lib/headline.js`; edit it there and run `scripts/sync-lib`.
- card.js: card pieces shared with agents-board (time in state, program icon, status glyph, PR colours, PR filter choices). Copy of `lib/card.js`; edit it there and run `scripts/sync-lib`.
- asking.js: the asking detector and its read queue. Copy of `lib/asking.js`; edit it there and run `scripts/sync-lib`.
- last.js: pure parser of the last message on a screen, for the eye button.
- check.svg, eye.svg, search.svg, columns.svg, chevron-down.svg, chevron-right.svg, clock.svg, filter.svg, layers.svg, pin.svg, pin-off.svg, spinner.svg, x.svg: icons.
- gpui-kit.d.ts, jsconfig.json: editor typings only.

## Settings and data
- Shared `agents-copy.sort` ("priority" | "grouped"; the old `agents.sort` is read when missing), `agents-copy.filter` ({ space, pr }), `agents-copy.remind` (0, 2, 5, 10 minutes).

## Notes
Asking detection: Claude Code reports `blocked` only for tool-permission prompts, so a menu of its own ("Enter to confirm", "Esc to cancel", a `❯ 1.` selector, `(y/n)`) shows as done/idle. Only choice menus count; a reply that merely ends in `?` does not. A footer phrase must start its line or follow a `·`, and a y/n marker must end its line, so a reply that quotes "(Y/N)" mid-sentence doesn't count. For each done/idle agent the mod runs `hc read <address>` (the screen only) and matches the last 14 lines above the input box for a menu. It reads again when the key `(address, turn, status, title)` changes: a new turn, done turning idle (the person looked at it, e.g. after dismissing a menu), or a new terminal title. The answer is kept per address (map capped at 200, dropped for agents that are gone, cleared when the agent works or is blocked). One read at a time; nothing on a timer; a redraw only when an agent's asking state changes.

The columns button in the header (hidden in rail mode) opens the `agents-board` mod with `mod.open`. If that mod isn't installed it shows a warning toast; everything else works without it.

Cloned from agents 0.1.15.

PR lookups: each cwd is resolved once to its git common dir (cache capped at 200), so worktrees share one `gh api graphql --cache 55s` call (open PRs, first 100: number, head branch, head commit's check rollup state; 15 s timeout). gh's disk cache is keyed by the request, so agents-board, with the same prs.js, shares the answer. One gh call runs at a time; a request meanwhile makes one more pass. gh is asked only for feature branches and Jira keys agents name (the PR of a key is matched in the same answer, by a branch holding the key; a repo with keys only, e.g. on its default branch, is asked on the same schedule): the default branch (`git symbolic-ref --quiet --short refs/remotes/origin/HEAD`, re-read every 30 min; without it `main` and `master`), a null branch and a detached HEAD are never asked, and a repo with none of them left gets no gh call. A feature branch not asked about yet is asked at once, then the repo every 5 min while none of them has an open PR, every 60 s while one has (5 min after a failure, keeping the last good answer). When an agent without a PR chip stops working (it may have just opened a PR), its repo is asked at once and once more 60 s later (gh's 55 s cache can hand the first ask the old answer), so a new PR shows within about 60 s. Agents of one repo stopping in the same minute share one recheck (it moves to 60 s after the last of them). If gh is missing or not logged in, chips disappear and it retries only every 10 minutes. At most 30 repos are cached; only number and checks state are kept. Redraws only when the PR map changes. The existing 30 s timer drives ticks and reminders; no other timers.
